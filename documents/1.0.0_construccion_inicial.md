# Documentación técnica: módulo Odoo 18 para dimensiones en líneas de venta

## Objetivo

Este módulo extiende **Odoo 18** para incorporar control de dimensiones en las líneas de cotización y pedido de venta (`sale.order.line`).

La funcionalidad agrega tres campos en las líneas de venta:

* `x_espesor`
* `x_ancho`
* `x_largo`

y aplica reglas de validación para asegurar que los valores ingresados cumplan con la parametrización definida por negocio.

Además, incorpora mantenedores en el módulo de **Ventas** para administrar:

* los espesores permitidos
* los rangos válidos de ancho y largo

El contenido base de esta documentación se ajustó a partir del material compartido. 

---

## Alcance funcional

El módulo permite:

* ingresar espesor, ancho y largo en cada línea de venta
* validar que el espesor corresponda a uno de los valores permitidos
* validar que el ancho quede dentro de un rango configurado
* validar que el largo quede dentro de un rango configurado
* administrar estas reglas desde mantenedores disponibles en el menú de Ventas

---

## Reglas de negocio

### Espesor

El campo `x_espesor` solo admite valores definidos en el mantenedor de espesores permitidos.

Ejemplo inicial de valores válidos:

* 40
* 45
* 55

La estructura del módulo permite registrar cualquier cantidad de espesores permitidos.

### Ancho

El campo `x_ancho` debe quedar dentro de un rango parametrizable.

Ejemplo inicial:

* mínimo: 600
* máximo: 1150

### Largo

El campo `x_largo` debe quedar dentro de un rango parametrizable.

Ejemplo inicial:

* mínimo: 2000
* máximo: 2400

---

## Arquitectura del módulo

La solución se implementa como un módulo Odoo estándar, de manera que:

* los campos se crean por código
* las validaciones se ejecutan en backend
* las vistas se definen por XML
* los menús y mantenedores quedan integrados al módulo de Ventas
* la funcionalidad puede instalarse desde cero en una base limpia

---

## Modelos implementados

### 1. Extensión de `sale.order.line`

El módulo hereda el modelo:

* `sale.order.line`

e incorpora los siguientes campos:

* `x_espesor`
* `x_ancho`
* `x_largo`

Tipo recomendado:

* `fields.Integer` para los tres campos

Estos campos quedan disponibles en las líneas de cotización y pedido de venta.

---

### 2. Modelo de espesores permitidos

Se define un modelo para administrar la lista de espesores válidos.

**Modelo técnico:**

* `sale.dimension.thickness`

**Campos principales:**

* `value`: valor del espesor
* `active`: indicador de vigencia
* `note`: observación opcional

**Validaciones recomendadas:**

* el valor debe ser mayor que cero
* no deben existir valores duplicados

**Uso funcional:**

* define los valores aceptados por `x_espesor`

---

### 3. Modelo de rangos de ancho y largo

Se define un modelo para administrar los límites válidos de ancho y largo.

**Modelo técnico:**

* `sale.dimension.range`

**Campos principales:**

* `name`
* `active`
* `width_min`
* `width_max`
* `length_min`
* `length_max`

**Validaciones recomendadas:**

* `width_min <= width_max`
* `length_min <= length_max`
* solo una configuración activa a la vez

**Uso funcional:**

* define el rango permitido para `x_ancho` y `x_largo`

---

## Validaciones implementadas

Las validaciones se implementan en backend mediante `@api.constrains`, sobre el modelo `sale.order.line`.

### Validación de espesor

Cuando `x_espesor` tiene valor:

* debe existir un registro activo en `sale.dimension.thickness` con ese valor

Si no existe, se debe bloquear el guardado con un mensaje de validación.

### Validación de ancho

Cuando `x_ancho` tiene valor:

* debe existir una configuración activa en `sale.dimension.range`
* el valor debe estar entre `width_min` y `width_max`

Si no se cumple, se debe bloquear el guardado.

### Validación de largo

Cuando `x_largo` tiene valor:

* debe existir una configuración activa en `sale.dimension.range`
* el valor debe estar entre `length_min` y `length_max`

Si no se cumple, se debe bloquear el guardado.

## Integración en vistas

### Vista heredada

El módulo hereda la vista:

* `sale.view_order_form`

**Modelo de la vista:**

* `sale.order`

### Inserción en líneas de venta

Se agregan los campos en `order_line`, en la grilla de detalle, idealmente después de la unidad de medida:

* `x_espesor`
* `x_ancho`
* `x_largo`

También se agregan al formulario interno de edición de la línea, para asegurar consistencia entre:

* edición en grilla
* edición detallada

---

## Menús y mantenedores

El módulo agrega acceso desde **Ventas** a un bloque de parametrización, por ejemplo:

* Ventas > Parámetros de dimensiones

Dentro de este bloque se exponen:

* **Espesores permitidos**
* **Rangos ancho/largo**

Esto permite administrar las reglas sin modificar código.

## Consideraciones técnicas para Odoo 18

Para evitar errores de compilación o renderizado en Odoo 18, el módulo debe respetar estas consideraciones:

* usar `@api.constrains` para validación de negocio
* alinear siempre las vistas XML con campos realmente definidos en el modelo
* heredar correctamente `sale.view_order_form`
* insertar columnas de `order_line` sobre la vista de lista correspondiente
* evitar referencias a campos inexistentes, ya que eso provoca errores de frontend tipo Owl
* en despliegues multi base de datos, instalar o actualizar el módulo por cada BD

---

## Instalación en una base limpia

Una vez copiado el módulo al `addons_path`, se debe:

1. actualizar la lista de aplicaciones
2. instalar el módulo en la base deseada

Ejemplo de instalación por consola dentro del contenedor Odoo:

```bash
docker exec -it <contenedor_odoo> odoo -d <base_de_datos> -i z_sale_dimension_rules --stop-after-init
```

Ejemplo de actualización:

```bash
docker exec -it <contenedor_odoo> odoo -d <base_de_datos> -u z_sale_dimension_rules --stop-after-init
```

## Resultado esperado

Con el módulo instalado sobre un Odoo limpio:

* las líneas de cotización y pedido de venta muestran los campos `x_espesor`, `x_ancho` y `x_largo`
* los espesores válidos se administran desde un mantenedor
* el rango permitido para ancho y largo se administra desde un mantenedor
* los datos ingresados se validan en backend antes de guardar
* la solución queda centralizada, mantenible y replicable

---

## Recomendaciones de uso

* no crear campos equivalentes manualmente desde UI si el módulo ya los define
* no duplicar la inserción de campos mediante vistas heredadas externas
* mantener la parametrización de espesores y rangos desde los mantenedores del módulo
* ejecutar instalación y actualización por cada base de datos en la que se requiera la funcionalidad

---

## Resumen

Este módulo incorpora control de dimensiones en líneas de venta para Odoo 18, mediante:

* campos adicionales en `sale.order.line`
* mantenedor de espesores permitidos
* mantenedor de rangos válidos de ancho y largo
* validaciones backend para asegurar consistencia de datos
* integración de vistas y menús dentro del módulo de Ventas

Su objetivo es permitir una instalación limpia y reproducible sobre Odoo 18, sin depender de personalizaciones manuales en UI.
